# Drop EAS: builds on the mini, our own OTA server

- **Date:** 2026-10-30
- **Status:** active, parked for someday (Sal 2026-10-30: "I'm not ready to do it but maybe someday"). Nothing built. Don't prune it
- **Type:** plan
- **What:** replace every EAS piece sal-starter forks use: builds and store uploads move to the Mac mini, OTA moves to a self-hosted Expo Updates server

## The short version

Keep Expo the framework (prebuild/CNG, config plugins, expo-modules, Router, dev client, fingerprint; expo-wsl-ios needs
it). Drop EAS the service: Build → the mini, Submit → `signing`/asc and the Play API, Update → our own server speaking the
open Expo Updates protocol, which the `expo-updates` client already talks to.

## Why

The mini is always on and builds iOS (since 2026-10-28) and Android (since 2026-10-30). `signing` already archives,
exports and uploads to TestFlight headlessly. EAS is left doing work we can do ourselves, and its cloud builders were the
source of every local-vs-EAS fingerprint mismatch (decisions.md, 2026-10-24).

## OTA (parked)

The client stays: `src/lib/ota.ts`, `useOtaHold`, `runtimeVersion: { policy: 'fingerprint' }`. Spec:
https://docs.expo.dev/technical-specs/expo-updates-1/

**`app.config.ts` changes**
- `updates.url` → our server instead of `u.expo.dev`.
- `updates.requestHeaders`: `expo-channel-name` per `APP_VARIANT` (replaces eas.json's build `channel`).
- `updates.codeSigningCertificate` + `codeSigningMetadata` (`keyid`, `alg: rsa-v1_5-sha256`), certificate from
  `npx expo-updates codesigning:generate`, committed; private key in the server's Drydock env. The certificate ships inside
  the binary, so it must be in the first binary that points at our server.

**Server: one multi-tenant `ota` app on Drydock** (new repo from sal-starter, Postgres + Prisma)
- Manifest route is plain HTTP, not tRPC: the protocol fixes it. Reads `expo-platform`, `expo-runtime-version`,
  `expo-channel-name`; returns the newest matching update as `multipart/mixed` (`manifest` part, or a `directive`
  part), `expo-protocol-version: 1`, `expo-sfv-version: 0`, `expo-signature` on each part,
  `cache-control: private, max-age=0`. Nothing to serve → 204.
- Assets content-addressed by their base64url SHA-256 (the hash the manifest already carries), in Drydock's `dataDir`,
  served `cache-control: public, max-age=31536000, immutable`, gzip/br. Unchanged files are stored once across updates.
- tRPC for publish, promote, rollback and list, driven by an `ota` CLI with `--json`:
  - `publish --channel preview`: `expo export` per platform, upload only the hashes the server lacks, create the update.
  - `promote preview production`: re-issue the tested update with a new id and `createdAt`, same assets (keeps
    decisions.md 2026-10-24: ship exactly what was tested).
  - `rollback --channel production`: re-promote the previous update, or serve `rollBackToEmbedded`.
- **Shipped-binary guard:** after each store upload the mini's build script registers (app, platform, variant,
  runtimeVersion, build number). Publish refuses a runtime version no shipped binary has: "native change: run the mini
  build". Fingerprint drift (mini vs WSL) becomes a refusal, not a crash on phones.
- Data: `App`, `Binary`, `Update` (uuid id, app, platform, channel, runtimeVersion, createdAt, gitSha, message),
  `Asset` (hash, contentType, size), `UpdateAsset` (update, asset, key, fileExtension, isLaunch).

**Not in v1:** bundle diffing, percentage rollouts (server-side later), a dashboard beyond a list.

**Migration:** the update URL is baked into each binary, so an app switches with its next store binary. Installs on the
old binary keep polling `u.expo.dev` until they update.

**App Review:** JS-only updates are allowed as long as they don't change what the app is (guideline 2.5.2); money and
data changes still go through a store build, same as the `app-review` skill's MVP rule.

**Unpark when:** the build side is done and Sal says go. Open then: the hostname (`ota.dested.com`?) and the pilot order
(sal-starter first so forks inherit it through `bun run sync`, then pickleball, which already uses `ota:*`).
