The base every new product starts from. One command turns it into a real app with a web server, an iPhone and Android app, and a desktop app, all sharing one API, one database and one look.

From zero to shipped

The order a new app goes through. The starter enforces the middle steps, so nobody skips them.

  1. Init

    bun run init <name> renames everything, picks unique ports, and with --mobile creates the EAS project.

  2. Kickoff

    Pick the look: one colour scheme, fonts, the real home page, the logo. Tests fail until it's done.

  3. Brand

    Draw one mark. bun run brand makes every icon, splash screen and favicon from it.

  4. Drop the demo

    bun run demo:drop removes the template's example feature and writes its migration.

  5. Ship

    Push to main and Drydock deploys the web app. Mobile ships through EAS builds and over-the-air updates.

What a new app has on day one

Accounts and access

  • Email and password sign-in on web and mobile, with the session on the first paint and no flicker
  • Sign-up allowlist: set SIGNUP_ALLOWLIST to emails or @domain entries, enforced by the server
  • Admins from ADMIN_EMAILS, with an adminProcedure for admin-only API calls
  • Back where you were: sign-in returns to the page you asked for, and off-site links are refused
  • No accounts at all with init --no-auth

Data and API

  • Postgres with Prisma 7, schema changes shipped as committed migrations
  • tRPC end to end: types flow from server to web, mobile and desktop with no codegen
  • Dates stay dates across the wire and through server rendering
  • Pages render with their data, prefetched on the server and on client navigation
  • Missing keys never break a deploy; the error names the Drydock setting to fill in

Mobile, pretty by default

  • A full-bleed splash in the brand colour that hands off to the app and fades out
  • Screen layout that handles safe areas, scrolling and the keyboard
  • Buttons with haptics and a press animation
  • Baseline libraries: images, fonts, SF Symbols, Lucide icons, toasts, fast lists, keyboard handling
  • Over-the-air updates that install on launch and resume, and a hold for screens mid-flow

Add-ons, one command each

  • bun run add:ai: Claude client with structured output, prompt caching, cost logging and a fake mode for tests
  • bun run add:ws: WebSockets and live tRPC subscriptions on the same server
  • bun run add:jobs: a Postgres job queue with retries and backoff
  • bun run upgrade:expo: Expo patch or SDK upgrades, with a report of what needs a new build

Guardrails that stop the usual mistakes

The demo can't ship

In any fork, the build and the tests fail while the example feature is present. The app shows it too:

Template demo · delete before shipping: bun run demo:drop

No look, no done

Until the kickoff sets the look, dev shows a "Kickoff pending" ribbon and bun run test fails.

One theme, ever

No dark mode and no toggle on any platform. The OS can't flip the app, and dark: classes never match.

Types are the gate

Strict TypeScript everywhere, no any, and zod at every boundary. A change isn't done while typecheck is red.

No brand-new packages

Every install waits 3 days after a release, on every machine and in every fork.

Tests that set themselves up

End-to-end tests create their own database, apply migrations and compare screenshots, in about 10 seconds.
